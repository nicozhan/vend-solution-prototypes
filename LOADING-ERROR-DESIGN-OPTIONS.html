现状诊断

为什么要换掉现在的做法

两个问题都不是"美化"问题，而是"信息缺失"问题：用户不知道是不是卡死了，也不知道出错了该点哪里。

问题 01

切换页面有白屏闪

每次打开原型页都会重建 iframe，旧页先被移除、新页还没渲染，中间是一帧纯白。弱网或页面较重时，这帧能停留 300–800ms，看起来像"点了没反应"。

问题 02

错误提示是居中黑块

深色胶囊居中弹出，正好压在用户正在看的内容上；没有图标、没有标题、没有"重试"，2 秒后自己消失，用户连发生了什么都没看清。

问题 03

所有错误长得一样

网络抖动、提交失败、开锁失败、登录过期都走同一个提示。用户无法判断"要不要重来"，也无法区分"我的操作错了"还是"系统出问题了"。

四条设计原则

  • 不遮内容。提示只能占用边缘（顶部 / 底部）的窄带，绝不落在视觉中心。
  • 先给答案，再给动作。标题说"发生了什么"，副文案说"下一步做什么"，右侧永远有一个可点的动作。
  • 时长与错误等级绑定。轻错误自动收，重错误等用户确认，不替用户做决定。
  • 品牌只在这种空隙里出现。加载是唯一适合放 Logo 的时机，但要克制：一个标记 + 三点，不做开屏动画。
方案 A

过渡 Loading · 品牌居中版

Logo + 三点 · 全屏遮罩

整块浅色遮罩盖住 iframe 区域，正中是 56px 品牌标记（蓝色方框 + 橙色勾），下方三点依次亮起，底部一行小字"正在加载"。这是最稳、最容易做对的一版：品牌露出、进度感、白屏被彻底盖住。

适用 / 代价

适合 跨模块进入、首屏、扫码后跳转、补货流程开始——这些场景用户愿意等 1 秒，也需要知道"是同一个 App 在干活"。

代价 列表 ↔ 详情来回切时会显得"重"，如果每次都要盖 300ms 以上，高频操作会觉得被拖住。所以必须配最短时长上限，且不叠加在已有遮罩上。

方案 B

过渡 Loading · 骨架先行版

骨架屏 + 顶部 2px 进度 · Logo 退到角标

不盖大遮罩。页面骨架（标题条、卡片块、列表行）立刻出现，顶部一条 2px 品牌渐变进度从左走到右；Logo 缩成 16px，和「正在载入点位」并排占住骨架第一行——品牌在场，但不占额外的屏。体感比 A 快，因为没有"先擦干净再画"的过程。

为什么这版体感更快

用户判断"快不快"看的是第一帧有没有内容，而不是总耗时。骨架在第一帧就有结构，视觉上等于"已经在加载了"；A 方案的第一帧是一块留白 + 小 Logo，虽然精致，但心理上还是"在等"。

过渡方案怎么选

两套不是二选一，是分场景
维度A · 品牌居中（Logo + 三点）B · 骨架 + 顶部进度
品牌感强。Logo 是视觉焦点，适合"第一次进入"弱。Logo 只剩角标，靠进度条表达状态
体感速度中。第一帧是留白，心理上"在等"快。第一帧就有结构，心理上"已到"
实现成本低。一个遮罩 + 3 个 keyframes，外壳层即可统一中。每页要一份同构骨架，跨页统一靠组件
失败兜底遮罩转顶部横幅，切换清晰骨架原地换错误块，信息不跳位
建议场景启动、扫码进入、跨模块（首页 → 统计）、补货流程列表 ↔ 详情、Tab 切换、筛选重载
最大风险高频跳转时显得"重"，拖慢节奏骨架与真实版式不一致，出现跳版
推荐组合

一套组件、两档强度：A 做"首次 / 跨模块"，B 做"页内"

不要全站只留一种。用户在同一个点位详情里反复开关筛选时，被一块 Logo 遮罩拦住 300ms 会很烦；但从首页点进"统计"时，没有品牌过渡又显得廉价。判定规则很简单：是否离开当前模块——离开用 A，不离开用 B。

A · 跨模块 / 首屏 / 扫码后B · 页内跳转 / 筛选重载B 可逐步铺，先做 4 个核心页

方案 D

错误提示 · 顶部下拉卡片

Sheet · 阻断 · 需确认

从屏幕顶端整块下拉，圆角 22 的白色卡片，带抓手、42px 语义图标、居中标题与原因，下面一个主按钮「重试」和一个次级「稍后再说」。背后压 30% 深色遮罩。这是"必须让用户知道并且做决定"的错误才用的规格。

它解决的是什么

开锁、提交工单、下单这类操作失败时，用户会反复点按钮、怀疑是不是自己没点中。横幅（方案 C）会自动消失，不足以让人停下来；下拉卡片把"失败"变成一个必须回应的时刻，并给出唯一正确的下一步。

错误分级与文案

先分级，再选组件

同一个错误用错组件，比没有提示更糟。判定只看一件事：用户现在还能不能继续干活。

等级典型场景组件是否阻断文案示例
L1 轻下拉刷新失败、图片加载失败、同步延迟顶部横幅（C）· 自动 3.4s否网络连接已断开，请检查后重试
L2 中列表 / 详情数据没回来、筛选后空结果顶部横幅 + 页内空态（C + 内联）否，内容区留「重试」点位数据加载失败
L3 重开锁失败、补货提交失败、工单提交失败、支付失败顶部下拉卡片（D）是，须确认左门开锁失败 · 电机未响应
L4 阻断登录过期、无权限、账号被停用全屏状态页（不在本次范围）是，只能重新登录登录已过期，请重新登录

文案怎么写

不要这样
  • 「操作失败」— 什么都没说
  • 「系统异常，请稍后再试」— 用户不知道该等多久
  • 「网络错误 (code: -1009)」— 把日志丢给用户
  • 「失败：无法连接到服务器，请检查您的网络设置并稍后重试」— 一句话塞三件事
建议这样
  • 标题 = 谁 + 怎么了：点位数据加载失败
  • 副文案 = 为什么 + 下一步：网络连接已断开，请检查后重试
  • 标题 ≤ 12 字，副文案 ≤ 24 字，两行内说完
  • 错误码只在 L3 出现，小字、等宽、置底

错误方案对比与结论

都不是"更好看"，而是"更对场景"
维度C · 顶部横幅D · 顶部下拉卡片
占屏约 66px，压在内容首行上约 260px，压住上半屏
是否阻断否，可继续滑动、点击是，遮罩拦截其余操作
消失方式3.4s 自动 + 手动只能用户确认 / 手势关闭
适合的错可自愈、可重试、不影响当前判断结果不确定、必须重来、涉及钱与门
连续出现可堆叠 2 条，同标题去重不允许堆叠，10s 内降级为横幅
成本低，一个组件全站复用中，需和遮罩、手势、焦点管理一起做
推荐落地

C 做默认，D 只留给"三件事"：开锁、补货提交、工单提交

现网的深色居中胶囊应该整体退役：成功类继续用底部轻提示（不打扰），失败类一律上移到顶部横幅，后果不确定的失败才升级为下拉卡片。这样"提示"和"错误"在空间上分开了——底部是"做成了"，顶部是"没做成"——用户用余光就能判断。

底部 = 成功顶部 = 失败下拉 = 需决策居中黑块 → 退役

还没定的三件事

  1. 过渡方案是"全站统一 A"还是"分场景 A + B"？分场景体感更好，但 B 要给每个页面单独做骨架，铺开需要排期。
  2. 深色胶囊是否全部退役？建议成功类保留（改到顶部会显得"出了事"），失败类全换。这需要确认现有哪些地方在用它。
  3. 下拉卡片要不要带"联系客服"？加上更稳，但会给客服带来量；不加则用户开锁失败后可能直接打电话给点位老板。
