01

定位与边界

先看这一节

这一层是设备主数据，不是设备资产。它回答三个问题：有哪些品牌、每个品牌下有哪些型号、每个型号装了哪些组件；以及反过来：一个组件被哪些品牌型号复用。它不回答「这个组件有哪些参数、值是多少、配方怎么配」——那是「组件与参数」（#/params/*）的职责。

判断一

品牌 / 型号是层级，组件是全局池

品牌 1—N 型号；组件不属于任何品牌，独立维护一份资料，通过「型号 × 组件」多对多复用。删除型号不能带走组件，删除组件必须先解绑。

判断二

指令代码挂在关系上，不挂在组件上

同一个上水水泵，在 WSD 1008/2008 是 power_A，在 TCN 680 是 pwr1，在 FUJI F100 是 fuji_pwr_1。所以指令代码是适配关系的属性，不是组件的属性。

判断三

数据点是「能力声明」，不是运行值

组件下的数据点定义类型、单位、范围、默认值，对齐物模型；真实读数属于设备实例。这里只维护 schema，不存遥测。

03

概念与数据模型

开发看这节

3.1 关系总览

品牌 1 ── N 型号 N ── N 组件 1 ── N 数据点
Brand(id,name,img)
   └─ Model(id,brandId,name,img)
         └─ ModelComponentLink(modelId,componentId,cmdCode)   // 多对多 + 关系属性
               └─ Component(id,name,cat)
                     └─ Point(pid,code,name,type,unit,min,max,step,scale,enumVals,def,required,enabled)

关键点：指令代码在第三张表上。如果把它放进组件表，就无法表达「同一个水泵在不同型号上指令不同」；如果放进型号表，就无法表达「一个型号有多个组件、每个组件各有一条指令」。

3.2 唯一性约束

对象约束实现口径冲突提示
品牌名称全局唯一去首尾空格 + 转小写后比较品牌名称已存在
型号名称同品牌内唯一跨品牌允许同名（如两个品牌都有「1008」）同品牌下已存在同名型号
组件名称全局唯一去空格 + 转小写比较组件名称已存在
数据点标识组件内唯一code 忽略大小写；不同组件可同名标识 code 在组件内已存在
适配关系（型号, 组件）联合唯一选择器已排除已关联项，保存时再判重没有新增适配关系（静默跳过）

3.3 级联与删除规则

操作前置条件结果样式
删除型号二次确认删除型号本体 + 该型号的全部适配关系；组件与数据点保留，其他型号不受影响不可恢复
删除品牌品牌下型号数 = 0有型号时只弹提示、不执行删除，要求先删除或转移型号当前一律拦截
删除组件适配型号数 = 0有引用时只弹提示、不执行删除，要求先解除全部适配当前一律拦截
移除适配无只删关系记录，组件资料、型号资料、数据点都不动；即时生效、无二次确认可恢复
!

现状缺陷：品牌和组件的删除入口没有做「数量为 0 就放行」。即使品牌下 0 个型号、组件 0 个引用，也只会弹「无法删除」并显示 0 个型号。开发时必须补上这个分支，否则主数据只能增不能删。详见 8.1。

3.4 指令代码生成规则

场景取值示例
默认值cmd_ + 组件 ID 去掉 C- 前缀后转小写，非法字符保留原样C-GRIND → cmd_grind
型号级覆盖同一组件在不同型号下可写不同值，互不影响C-PUMP → power_A / pwr1 / fuji_pwr_1
添加时修改选择器每行右侧的输入框，可逐条改勾选「磨豆电机」，把 cmd_grind 改成 grind_1
添加后修改抽屉或适配浏览表格里点指令代码单元格，行内编辑；Enter 确认、Esc 取消——
校验非空；允许字母、数字、下划线、连字符；不做全局唯一空值 → 指令代码不能为空

3.5 数据点（物模型定义）

数据点只存在于组件上，用来声明「这个组件能读/能写什么」。类型决定字段集：

类型中文专属字段范围展示
bool开关默认值（开 / 关）—
value数字单位、最小值、最大值、步长、精度0 ~ 99 s
enum状态枚举值列表（可增删）、默认值从列表选低速 / 中速 / 高速
string字符串默认值；本期不设长度约束—
raw透传Hex 透传；本期不设约束—

公共字段：名称、标识 code、类型、必填、启用。表格列固定为：名称 / 标识 / 类型 / 单位 / 范围 / 默认值 / 必填 / 启用 / 操作。

i

数据点与「组件与参数」里的参数不是一回事。数据点描述通信能力（读什么、写什么、什么类型），参数描述设备行为（水量、搅拌速度）。同一个组件可以既有数据点，又在参数模块里挂参数，两者不要合并成一张表。

逐页拆

4.1 品牌（#/devicecfg/brand）

用途：维护设备制造商。品牌是型号的父级，本身不承载业务参数。

页面标题
品牌型号与组件 / 品牌；副标题「管理设备制造商与品牌。」
主操作
右上角「＋ 新增品牌」，蓝色实心按钮
筛选栏
仅一个「搜索品牌」输入框，按名称即时过滤（不区分大小写）；无状态筛选、无分页
表格列
图片（32px 正方形）· 品牌名称 · 型号数量（数字，不可点）· 更新时间 · 操作（编辑 / 删除）
计数
表头右侧「共 N 项」，随筛选结果变化
行内操作
编辑 → 打开编辑弹窗；删除 → 打开拦截/确认弹窗
空状态
无数据：「暂无品牌，添加第一个品牌。」；搜索无结果：「未找到匹配结果。」

新增 / 编辑品牌弹窗

字段必填规则
品牌名称是文本框，最多 50 字；去首尾空格；全局唯一
图片否点击方框或「选择图片」上传；JPG / PNG；上传后居中裁切为 1:1，最长边压到 512px；可「移除图片」

弹窗宽度 620；标题「新增品牌 / 编辑品牌」，副标题「品牌型号与组件」；底部「取消 / 保存」。保存成功后关闭弹窗、列表刷新、右下角 toast「品牌创建成功 / 已更新」。

4.2 型号（#/devicecfg/model）

用途：维护品牌下的具体机型，并管理机型装了哪些组件。

主操作
「＋ 新增型号」
筛选栏
品牌下拉（全部品牌 / 具体品牌）+ 搜索框（同时匹配型号名与品牌名）
表格列
图片 · 品牌 · 型号 · 组件数量（可点，开「管理组件」抽屉）· 更新时间 · 操作（管理组件 / 编辑 / 删除）
排序
按录入顺序，不排序、不分页
空状态
「暂无型号，添加一个型号。」；筛选无结果：「未找到匹配结果。」

新增 / 编辑型号弹窗

字段必填规则
品牌是下拉，选项来自全部品牌；新增时默认取当前筛选的品牌，否则取第一个品牌
型号名称是最多 50 字；同品牌内唯一
图片否同上，1:1 裁切

删除型号确认

弹窗标题「删除型号」，正文说明「将同时清理 N 条组件关联记录；全局组件资料不会被删除」，并以红色提示「此操作不可恢复」。按钮「取消 / 确认删除」（危险色）。

4.3 组件（#/devicecfg/component）

用途：全局组件库。一个组件只维护一份资料，可被多个品牌型号复用；组件上带数据点定义。

主操作
「＋ 新增组件」
筛选栏
搜索组件（名称）+ 分类下拉（全部分类 / 料道 / 清洗 / 非料道）
表格列
组件名称 · 分类（两级徽标，如「料道 · 豆仓」）· 适配型号（最多显示 2 个「品牌 / 型号」，超出显示「+N 更多」）· 型号数量（可点）· 操作（管理适配 / 编辑 / 删除）
分类徽标配色
料道 → 蓝；清洗 → 绿；非料道 → 灰；未分类显示「—」
空状态
「暂无组件，添加第一个组件。」；筛选无结果：「未找到匹配结果。」
!

分类筛选只按一级过滤。选「料道」会带出料道下全部子类，但没法直接选「料道 / 豆仓」。数据里已经有两级，筛选器只做了一级——要么补二级联动，要么明确「列表只按一级筛、精确到子类靠搜索」。

新增 / 编辑组件弹窗（宽 820）

区块内容
基本信息组件名称（必填，≤50，全局唯一）+ 分类（下拉：未分类 / 料道·粉料 / 料道·BIB / 料道·豆仓 / 料道·水 / 料道·冰 / 料道·液体 / 清洗 / 非料道）
数据点区标题「数据点 / 传感器（N）」；右上「从其他组件复制」「＋ 新增数据点」；下方 9 列表格，最大高度 300，内部滚动
数据点表格名称 / 标识 / 类型 / 单位 / 范围 / 默认值 / 必填 / 启用（勾选框，即时改）/ 操作（编辑 / 删除）
空数据点「暂无数据点，点击「新增数据点」或「从其他组件复制」。」

注意：组件没有图片字段。品牌和型号都有 1:1 图片，组件没有；列表首列直接是名称。如果后续要在选型、报表里出图，需要补。

数据点弹窗（宽 620）

字段必填规则
名称是如「研磨时间」
标识 code是以字母开头，仅字母 / 数字 / 下划线；组件内唯一（忽略大小写），如 grind_time
类型是开关 / 数字 / 状态 / 字符串 / 透传；切换类型时下方字段联动
单位 / min / max / step / scale否仅数字型；min 不得大于 max；step、scale 为数字
枚举值至少 1 个仅状态型；输入后「添加」，列表内可逐条删除
默认值否开关型为开/关；状态型从枚举值中选；其他为文本框
必填 / 启用否两个勾选框，默认「启用」勾选、「必填」不勾

从其他组件复制数据点（宽 620）

  1. 选择源组件（排除当前正在编辑的组件）。
  2. 列出源组件的全部数据点，逐条勾选；显示「名称 · 类型 · code」。
  3. 「复制所选」：深拷贝生成独立副本，编辑互不影响；pid 重新生成；若 code 与目标组件已有项冲突，自动加 _1、_2 后缀。
  4. 复制结果先进入编辑态列表，仍要在组件弹窗点「保存」才真正落库。

5.2 关联组件（核心链路）

  1. 型号行点「管理组件」（或点组件数量）→ 右侧抽屉打开，标题「管理组件」，副标题「品牌 / 型号」。
  2. 抽屉列出已关联组件：名称、分类、指令代码、移除；底部「共 N 个组件」。
  3. 点「＋ 添加组件」→ 打开选择器。列表自动排除已关联组件，支持按名称搜索。
  4. 逐条勾选，每行右侧可直接改指令代码；默认值按 3.4 生成。
  5. 找不到？底部输入新组件名称 →「新建并关联」：全局创建组件（分类为空），并立即建立当前型号的关联。
  6. 「添加所选」→ 仅新增未关联项；提示「已添加 N 条适配关系」，若全已存在则「没有新增适配关系」。
  7. 抽屉内「移除」即时生效，不弹确认；提示「已解除适配关系，组件资料保留」。

5.3 关联型号（反向）

组件行点「管理适配」→ 抽屉列出使用该组件的型号（品牌 / 型号 / 指令代码 / 移除）。「＋ 添加型号」的选择器支持品牌筛选与跨品牌多选，同样排除已关联项。其余规则与 5.2 对称。

5.4 指令代码行内编辑

进入

校验

5.5 图片上传

  1. 点方框或「选择图片」→ 唤起文件选择，仅 image/*。
  2. 非图片文件 → 提示「请选择图片文件」。
  3. 读取后按短边居中裁切为正方形，输出最长边 512px 的 PNG。
  4. 预览立即更新，提示「图片已裁切为 1:1 方形」；读取失败提示「图片读取失败」。
  5. 「移除图片」清空，回到占位态。
  6. 图片在点「保存」前只存在于编辑草稿里；取消则丢弃。

5.6 保存语义

操作生效时机未保存就关闭
品牌 / 型号基本信息点「保存」后丢弃
组件名称 / 分类点「保存」后丢弃
数据点的增 / 改 / 删 / 复制先进入组件弹窗的草稿，点组件「保存」才落库整批丢弃

指令代码回车/确认即时生效已生效

6.3 并发与一致性（后端落地时必须处理）

  • 名称唯一性：前端判重只能挡住同一会话，后端必须加唯一索引（品牌名、组件名全局唯一；型号名按 brandId 唯一）。
  • 关联并发：两个人同时给同一型号加同一组件，后端用 (modelId, componentId) 联合主键或唯一索引兜底，重复时幂等返回。
  • 删除与引用：删除品牌 / 组件时，后端要在事务里再校验一次引用数，不能只信前端弹窗。
  • 删除型号：级联删关联必须在同一事务内；组件资料不得被误删。
  • 更新时间：新增 / 编辑 / 新增关联时刷新；移除关联时也应刷新（现状没刷新）。

权限与审计

现状是「都能改」

现状：这一层没有任何角色隔离。只要进得了后台，就能新增、编辑、删除品牌型号组件，也能改指令代码。原型阶段可以接受，上线前必须补。

角色查看新增 / 编辑删除说明
平台管理员✓✓✓主数据唯一维护方
运维 / 实施✓建议只读—需要查适配关系，但不该改结构
租户管理员✓——只读自己设备涉及的品牌型号

审计日志（建议字段）

who      操作人 + 角色
when     时间
action   create / update / delete / link / unlink / cmd_change
object   brand | model | component | point | link
target   对象 ID + 名称（删除后仍可追溯）
diff     变更前后（至少记录名称、分类、指令代码）

最低要求：删除型号、删除关联、改指令代码这三类必须留痕，因为它们会直接影响下发。

已知问题与差距

按优先级

下面这些是逐行读实现 + 页面实测得到的，不是猜测。P0 建议在下一版就修。

优先级问题现状建议
P0 品牌删除无条件拦截 不管品牌下有几个型号，一律弹「无法删除品牌」；0 个型号时显示「存在 0 个型号」，仍然删不掉 数量为 0 时改为「确认删除」；大于 0 才拦截
P0 组件删除无条件拦截 同上，0 个适配型号也删不掉 同上
P0 数据点删除无确认、无引用检查 表格里点「删除」立即从草稿移除；若该数据点已下发到设备，物模型会出现悬空字段 删除前检查是否已被设备/参数引用；至少加二次确认
P1 数据不持久 全部存在内存，刷新即恢复初始 4/6/11；图片是 dataURL，也不落库 接后端；图片走对象存储，表里只存 URL
P1 型号删除不检查设备占用 只要有权限就能删，即使该型号下已有在线设备 与机器资产联动：有设备时禁止删或要求先迁移
P1 列表无分页 / 无排序 全量渲染，按录入顺序；组件多了以后难找 补分页 + 按名称 / 更新时间排序
P1 移除关联不可撤销 点「移除」立即生效，只给一条 toast toast 带「撤销」，或改为二次确认
P2 移除关联不刷新「更新时间」 新增关系会刷新，移除不会，时间线不准 两个方向都刷新
P2 组件分类筛选只到一级 只能选「料道 / 清洗 / 非料道」，选不了「料道 · 豆仓」 补二级联动，或列表加子类列
P2 组件没有图片 品牌、型号都有 1:1 图，组件没有；列表首列是名称 统一字段，或明确「组件不需要图」
P2 切换标签清空筛选 在型号页筛了 WSD，去组件页再回来，筛选没了 按标签分别记忆筛选状态
P2 品牌「型号数量」不可点 型号的组件数量可点开抽屉，品牌的型号数量只是数字 点击跳到型号页并带上品牌筛选
P2 无导入 / 导出 / 批量 只能一条条录；初始化 30 多个型号会很痛苦 补 CSV 导入、列表导出、批量关联
!

最该先修的是「能增不能删」。主数据模块如果删不掉错录的品牌和组件，实际使用第一周就会堆满脏数据；而维护人员没有别的入口清理。这一条不修，后面补分页、补图片都没有意义。

待确认

需要你拍板
品牌 / 型号要不要启用停用
现在只有增删改。停售机型如果直接删，会连带清掉历史关联；建议加「状态」字段，停用后不出现在新增设备的下拉里。
指令代码要不要全局唯一
现在只保证非空、按关系存。如果下发网关按「指令代码」路由，同名会串台；如果按「型号 + 代码」定位，则无需唯一。这决定后端要不要加唯一索引。
组件是否要版本
组件资料一改，所有引用它的型号同时变。若不同批次设备用的硬件不同，需要「组件版本 + 型号锁定版本」，否则改一个水泵会影响全部机型。
型号下已有设备时能不能删
现在能。删完设备会变成「找不到型号」的孤儿。建议改成：有设备则禁止删除，只允许停用。
删除品牌要不要支持「连同型号一起删」
现在强制先删型号，品牌多了会很繁琐。可提供「级联删除」但要求输入品牌名二次确认。
组件分类要不要三级
现在是「料道 / 子类」两级。BIB、冰、液体是否还需要再分（如「冰 · 冰块 / 冰 · 冰沙」）？这会影响筛选器和报表分组。
数据点要不要读写方向与上报频率
现在只有类型和范围。物模型通常还需要 read/write、上报周期、是否必报。要和 IoT 平台对齐后再定字段。
BMW 演示数据怎么处理
「档把 / 方向盘 / 后视镜」明显是分类压力测试。上线前删除，还是保留成「非料道示例」？
