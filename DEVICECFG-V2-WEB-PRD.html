01

定位与边界

先看这一节

这一层解决的问题只有一句话：把一台机器拆成可复用的零件和配方，让 1008 系列到 6008 共用一套配置方式。拆错了，后面每加一个机型都要改一次代码。

1.1 三条判断标准

标准一

组件是「类型」，装机是「实例」

6008 装 3 个蠕动泵、1008 与 1008I 都可能有落杯和落盖。同一个组件定义，在一个型号上可以出现多次，各自有工位、料仓和指令代码。

标准二

配方认「原料」，不认「组件」

运营只选原料和水量，系统顺着 原料 → 料仓 → 组件实例 → 参数模板 自动带出可调项。让运营选组件，等于把工厂的活推给门店。

标准三

克数说了算，秒数算出来

配方里写「粉 9.5 g」，出料时长由校准表换算。固定时间校准被废止，换粉料品牌必须重校，否则每杯都会偏。

1.2 做什么 / 不做什么

范围包含不包含（去哪看）
做 机型主数据（品牌 / 型号 / 变体）、全局组件库与装机实例、料仓与原料绑定、商品级制作配方、清洗策略、多档位校准、机型档案、型号级远程能力与设备级远程任务 ——
不做 设备实时状态、订单与支付、库存补货、点位管理、报表分析 设备监控 / 运营分析 / 商品中心，本文不定义
不做但要点名 原料主数据的完整档案（只定义本模块用到的 6 个字段） 供应链 / 原料管理，本期以引用方式存在
明确不做 把副柜、灯箱、外观尺寸当组件管理 这些是结构规格，进「基本信息」，不进组件库
i

为什么结构件不能进组件库：组件库的每一个条目都要能被「勾选 → 带出参数 → 下发」。副柜、灯箱没有可下发参数，一旦混进去，装机清单里就会出现一堆勾了没反应的条目，运营会以为系统坏了。结构差异属于型号档案。

1.3 与现有文档的关系

文档关系处置
DEVICECFG-WEB-PRD.html v1.0只覆盖品牌 / 型号 / 组件 / 适配浏览四页，配方与清洗标注「见另一份文档」但那份并不存在本文取代
原型 #/params/formula、#/params/clean上一轮按「选组件 → 选参数」做的，与会议结论冲突需重做
《配方与工艺》118 项参数那是设备固件的工艺参数字典，与商品配方不是一回事保持独立

本文只描述「配置」，不描述「运行」。所有页面都不展示实时数据，实时值在设备监控里看。

2.2 十个概念，一句话分清

概念是什么容易混淆成生存期
品牌 Brand设备制造商经销商、客户公司长期
型号 Model一个可售机型，如 1008I某一台设备长期
型号变体 ModelVariant基础型号 + 选配包，如 1008I-P新型号。它不新增组件，只加选配随型号
组件 Component电气/控制硬件的定义，全局唯一某个位置上的零件长期
组件实例 ModelComponent某型号上「第 n 个」该组件，带工位、数量、指令代码组件本身。实例删了定义还在随型号
料仓 Silo型号上的物理仓位，装一种原料组件。仓位通常挂在一个实例上，但两者不同随型号
原料 Material粉 / 豆 / 糖浆 / 茶叶 / 液体商品。商品是卖的东西，原料是耗的东西长期
制作配方 Recipe商品规格的步骤式制作说明设备参数。配方是「怎么做」，参数是「机器怎么动」随商品
校准 Calibration原料 × 组件实例 × 转速档 的「克数 ↔ 时长」换算表配方。校准是尺子，配方是用尺子量出来的值随机型/机器
远程能力 RemoteCap型号允许哪些远程动作，及互锁条件具体任务。能力是开关，任务是执行记录随型号
i

最容易被合并错的两组：① 组件 ≠ 组件实例。合并后 6008 的三个蠕动泵就表达不了。② 配方 ≠ 参数。合并后「换一个牌子的粉」要动整套设备参数，而实际只需要重做校准。

2.3 唯一性与级联

对象唯一性级联规则
品牌名称全局唯一（忽略大小写与首尾空格）有型号时禁止删除，提示先迁移
型号名称同品牌内唯一有设备或已下发配方时禁止删除，只允许停售
型号变体 SKU全局唯一随基础型号删除
组件名称全局唯一被任意型号引用时禁止删除；删除时给「先解除 n 处引用」
组件实例（型号, 组件, 工位）唯一删除前必须解绑料仓、清空清洗与校准记录
料仓号同型号内唯一有绑定原料且有余量记录时，只能停用不能删
配方步骤（规格, seq）唯一删除步骤后续 seq 自动重排
校准记录（型号, 实例, 原料, 转速档, 版本）唯一新增即新版本，旧版本保留可追溯，不物理删除
远程任务（设备, 动作, 发起时间）唯一不允许删除，只追加状态

2.4 从原型到新模型：7 处必改

项原型现状本文定义不改的后果
P0 型号-组件多对多，(型号,组件) 联合唯一型号-组件实例，允许同组件多次，带工位与数量6008 三个蠕动泵只能造假组件，污染全局池
P0 选配无，靠新建型号基础型号 + 选配包，生成变体 SKU-P 组合爆炸，1008 一支变四个型号
P0 料仓不存在独立实体，绑组件实例与原料配方无法从原料反查参数，只能让人手点组件
P0 配方18 项平铺参数一次配完步骤式，商品 × 规格，支持型号覆盖做不出「第 3 步只加 40ml 热水」
P0 校准不存在，靠固定时间多档位称重换算出料时长换粉料品牌后每杯克数都偏，客户第一周就会投诉
P1 清洗人工勾选参与 + 时长/次数/用水触发条件（定时 / 计数 / 单杯）+ 跟随使用「省水」这个核心目的落不了地
P1 远程不存在型号能力开关 + 设备级任务记录现场故障只能派人，OTA 无法灰度

3.3 上下文选择器：每页都要带，但不重复选

平级页签最容易做坏的地方是「每进一页都要重选一遍型号」。规则定死三条：

规则具体做法
会话内记忆品牌 / 型号选择存在 URL 参数与本地状态里。在料仓选了 1008I，切到清洗、校准、基本信息，仍是 1008I。刷新页面也保持。
深链可直达#/devicecfg/silo?model=MK-1008I 打开即定位。无效型号回退到该品牌第一个，不白屏。
不适用就隐藏品牌页不显示选择器；制作页换成「商品 + 规格 + 生效机型」；组件页显示型号但右侧装机面板才受它影响。
!

原型现存缺陷：切换标签会清空筛选，在型号页筛了 WSD，去组件页再回来筛选就没了。新 PRD 要求按页签分别记忆，这条写进验收（H1）。

4.2 型号与变体

型号是整套配置的锚点。变体不是新型号，它只是在基础型号的装机清单上追加若干组件实例，再生成一个可售 SKU。

字段约束说明
型号名称必填，同品牌内唯一跨品牌允许同名（两个品牌都有「1008」）
所属品牌必填创建后不可改，需要改就新建
系列必填1008 系列 / 6008 系列；影响列表分组与默认组件包
结构代号必填C / 标准 / I，决定副柜与灯箱，详见「基本信息」
状态在售 / 停售 / 草稿草稿不进设备下拉；停售不影响已有设备
装机组件数只读来自组件页，点击跳转

基础型号选配包生成 SKU说明

选配包里装的是什么：一组组件实例。例如 P 包 = 加装「压杯盖机构」1 个实例 + 落盖工位 1 个。所以变体的差异最终落在组件页的装机清单上，而不是在型号表里加布尔字段。这样以后新增选配（例如加装第二组糖浆泵）不需要改表结构。

支付外设和数值参数不是一类东西。纸币器、刷卡器的配置是「协议 / 地址 / 波特率 / 币种」，没有 min-max 范围。这类组件在参数模板里要用 enum 与 string 类型，不要硬塞进数值型校验，否则保存时会被「必须有单位、必须有范围」的规则挡住。

下面 10 条会改变数据模型或页面结构，建议在开发启动前逐条确认。带「建议」的是我的倾向，可以直接采纳或否掉。

#问题为什么卡住建议
11008EG 与 1008 / 1008C / 1008I 是什么关系？原型用的是 MK-1008EG，会议里是 1008C / 1008 / 1008I。命名映射不清，型号主数据无法落地确认 1008EG 是否就是 1008I 的客户叫法；PRD 统一改用会议命名
2-P 是后缀还是拼在型号里？1008C-P 和 1008CP 两种写法都出现过，影响 SKU 规则与打印统一 基础型号-P，如 1008C-P
33 个蠕动泵是「一个组件 3 实例」还是「3 个糖浆组件」？决定组件库要不要拆，也决定校准是按泵还是按糖浆一个「蠕动泵」组件 + 3 个实例，实例绑不同料仓
4「出水间隔」到底存不存在？会议说水路无出水速度调节、靠流量计控量，但上一轮需求里有「出水间隔 s」先按配方步骤的「分段进水」处理，不作为设备参数
5单杯清洗开关能否远程改写？会议说在设备本地设置；后台若可改，会与本地设置冲突，需要定优先级后台只读展示，本地优先；远程可「临时开启一次」
6校准数据归属：机型级还是机器级？机型级省事但忽略现场差异，机器级准确但要逐台做机型出默认值，机器可覆盖，配方引用机器实际值
7水粉比的口径是 1:8 还是 ml:g？包装袋上写法不一，提醒阈值算错会误报或漏报统一存「每 1 g 粉对应多少 ml 水」的数值，界面显示为 1:8
8冷 / 热用两个 SPU 还是一个 SPU 两个规格？会议说「由客户自行选择使用方式」，但系统必须选一种主模型一个 SPU 多规格，规格带价格；需要拆成两个 SPU 的客户用「商品复制」实现
9支付外设（纸币 / 硬币 / 刷卡 / 小票）进组件库吗？它没有配方参数，但需要下发协议配置，形态与其他组件不同进组件库，单独一级分类，参数用协议 / 地址 / 波特率
10远程锁机要不要做？涉及欠费风控与消费者权益，可能有合规风险本期只做能力位与审计，不开放给非管理员；上线前需法务确认
